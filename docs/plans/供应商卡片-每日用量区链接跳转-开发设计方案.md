> 文档类型：开发设计方案
> 关联模块：供应商卡片（每日用量 / 增量区）
> 创建时间：2026-10-10
> 最后更新：2026-10-10

> 关联改动文件：`src/types.ts`、`src/providers/base.ts`、`src/service.ts`、`src/providers/sessionApi.ts`、`src/providers/presets.ts`、`src/providers/demo.ts`、`src/providers/a1etheropenai.ts`、`src/providers/{qoder,trae,codebuddy,codearts}.ts`、`public/index.html`、`public/styles.css`、`public/app.js`、`README.md`

## 1. 背景与目标

**结论：给四张卡片（CodeBuddy / Trae / CodeArts / Qoder）的「每日用量」区整块加上外链跳转，点击直达对应平台的用量页，从看板一键核对明细。**

现状痛点：用量区只展示四个数字，想核对「昨日/今日用量、增量」的来龙去脉必须自己手输平台地址；卡片 footer 虽已有「打开面板」，但它挂在 `dashboardUrl` 上（语义是面板入口），并非所有平台都指向用量页。

用户给定的四个用量页：

| 平台 | 用量页 URL |
| --- | --- |
| CodeBuddy | `https://www.codebuddy.cn/profile/plans-usage` |
| Trae | `https://www.trae.cn/dashboard#usage` |
| CodeArts | `https://codearts.huaweicloud.com/portal/settings/personal-usage?locale=zh-cn` |
| Qoder | `https://qoder.cn/account/usage?client=qoder&sourceType=IDE` |

Non-Goals：

- 不改四字段的口径与数据源（沿用 `docs/plans/供应商卡片-用量与增量字段-开发设计方案.md`）。
- 不改 footer「打开面板」的链接与其 `dashboardUrl` 语义。
- 不做悬浮明细弹层、不做单字段级别的跳转。

## 2. 现状调研

**结论：用量区目前是纯展示的 `div`；卡片虽有外链能力（`dashboardUrl`），但其语义是「面板入口」，不能直接复用于用量区。**

关键证据：

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 用量区渲染 | `public/app.js:516-553`（`renderUsage`） | 2×2 网格，字段定义见 `public/app.js:28-57` |
| 用量区模板 | `public/index.html:101-104` | `<div class="usage">` + `.usage__grid`，无任何链接能力 |
| 卡片外链现状 | `public/app.js:495-500`、`public/index.html:166-169` | footer「打开面板 ↗」用 `provider.dashboardUrl` |
| 契约现状 | `src/types.ts:176-182`、`src/providers/base.ts:30-32`、`src/providers/base.ts:242-243` | `dashboardUrl` 由适配器声明、`buildSnapshot` 透传 |
| 失败快照手写处 | `src/service.ts:162-163`、`src/service.ts:227-228` | 不走 `buildSnapshot` 的两处需同步补字段 |

用户给定 URL 与现 `dashboardUrl` 比对：

| 平台 | 现 `dashboardUrl` | 与给定 URL 的差异 |
| --- | --- | --- |
| CodeBuddy | `src/providers/codebuddy.ts:161` | 一致 |
| Trae | `src/providers/trae.ts:229` | 一致 |
| CodeArts | `src/providers/codearts.ts:227` | 少 `?locale=zh-cn` |
| Qoder | `src/providers/qoder.ts:225`（`qoder.com.cn`） | 域名与参数均不同 |

A1etherOpenAi 的 `dashboardUrl` 指向 api-key 设置页（`src/providers/a1etheropenai.ts:71`），进一步说明「面板入口 ≠ 用量页」，两语义必须分开。

同名不同域提醒：`npm run capture` 的抓包目标配置里也有 `usageUrl`（`src/cli/capture.ts:110-145`），那是「调试浏览器打开哪个页面」，与本次快照字段不同层级、互不联动（其中 Qoder 抓包目标为 `qoder.com.cn`，见 `src/cli/capture.ts:121`）。

## 3. 方案设计

**结论：在适配器契约新增独立字段 `usageUrl`（与 `dashboardUrl` 解耦、空串表示无用量页），快照透传到前端；前端把 `.usage` 由 `div` 改为 `<a>`，仅 `usageUrl` 非空时激活跳转。**

数据流：

```
适配器声明 usageUrl（四个平台）
  → buildSnapshot()/失败快照写入 ProviderSnapshot
  → /api/summary（不变）
  → app.js renderUsage()：usageUrl 非空 → 设 href/aria，加 .usage--link
  → 浏览器新窗口打开平台用量页
```

行为约定：

| 场景 | 行为 |
| --- | --- |
| `usageUrl` 非空（四平台） | 整个用量区可点：hover/focus 淡蓝底 + 内描边、指针变手型、`aria-label="打开 <平台> 用量页（新窗口）"`；`target="_blank"` + `rel="noreferrer noopener"` 新窗口打开 |
| `usageUrl` 为空（A1etherOpenAi、custom、示例·无过期时间） | 完全保持现状：纯展示、无 hover 变化、不可点 |

关键取舍：

- **为什么不复用 `dashboardUrl`**：语义不同（面板 ≠ 用量页）；A1etherOpenAi 会指向 api-key 设置页，产生误导。
- **为什么不前端硬编码 URL 映射**：平台地址属适配器层配置（仓库惯例：`dashboardUrl` / `credentialHint` 都在适配器声明），前端保持「不认识平台名」。
- **为什么整块可点而不是加小链接**：用户诉求是「对显示区添加链接跳转」，整块是最直接的实现；也避免了窄卡片下新增一行破坏 2×2 布局。

## 4. 接口设计

**结论：无新增/变更 HTTP API；仅扩展 `ProviderAdapter` 契约字段。**

- `/api/summary` 出参在 `ProviderSnapshot` 上新增 `usageUrl`（见第 5 节），其余字段与错误码不变。
- `ProviderAdapter` 新增必填字段 `usageUrl: string`（`src/providers/base.ts`），无用量页的平台写空串。

## 5. 数据模型

| 字段 | 类型 | 语义 | 位置 |
| --- | --- | --- | --- |
| `ProviderAdapter.usageUrl` | `string` | 平台用量页地址；空串 = 不提供跳转 | `src/providers/base.ts` |
| `ProviderSnapshot.usageUrl` | `string` | 同上，透传给前端 | `src/types.ts` |
| `SessionApiPreset.usageUrl` | `string` | custom 预设为 `''` | `src/providers/sessionApi.ts` |
| `DemoDefinition.usageUrl` | `string` | 示例数据按真实平台用量页填充；无过期示例为 `''` | `src/providers/demo.ts` |

不涉及 `accounts.json` / `.env` 变更，无配置迁移。

## 6. 影响面评估

| 层 | 影响 | 说明 |
| --- | --- | --- |
| 适配器（5 内置 + custom + 5 示例） | 需补 `usageUrl`（`ProviderAdapter` 字段必填，编译期强制） | 四平台填用户给定 URL；A1etherOpenAi 填 `''`；示例按对应平台填充 |
| 编排层 | `src/service.ts` 两处手写快照补 `usageUrl` | `:162`（未知平台）、`:226`（探测异常） |
| 聚合层 | 无改动 | `groupSnapshots` 直接沿用卡片快照（`src/aggregate.ts:36-56`） |
| 前端 | `public/index.html` 模板、`public/styles.css`、`public/app.js` 的 `renderUsage` | footer 链接、排序/筛选/搜索均不受影响 |
| 缓存 / 到期时间线 | 无影响 | 不涉及 `service.ts` 缓存与 `aggregate.ts` 时间线 |
| README | 「新增一个平台」示例补一行 `usageUrl` | `README.md:585` 附近 |

## 7. 风险与备选方案

| 风险 | 缓解 |
| --- | --- |
| 整块可点导致误触 / 影响文字选择 | 仅 `usageUrl` 非空的四平台激活；无 href 的平台保持旧行为；hover 才有高亮，可预期 |
| `.usage` 由 `div` 改 `<a>` 后 `display:block` 会盖掉 UA 的 `[hidden]` 规则 | 显式补 `.usage[hidden] { display: none; }`（与 `.card__link[hidden]` 的既有做法一致，`public/styles.css:1144`） |
| Qoder 卡片用量页取用户给定的 `qoder.cn`，与抓包目标的 `qoder.com.cn`（`src/cli/capture.ts:121`）域名不同，跳转后可能要求重新登录 | 两个入口互不影响；若上游实际以 `qoder.com.cn` 为准，只需在 `src/providers/qoder.ts:226` 单点改 URL |
| 上游改版更换用量页地址 | URL 单点在适配器维护，前端无需改动 |

备选方案：

- **复用 `dashboardUrl`（否决）**：A1etherOpenAi 等平台的 `dashboardUrl` 语义不符，会误导跳转。
- **前端按 provider id 硬编码 URL（否决）**：配置散落前端，违背适配器层声明惯例。

## 8. 实施步骤

1. `src/types.ts` 新增 `ProviderSnapshot.usageUrl`（JSDoc 说明与 `dashboardUrl` 的区别）。
2. `src/providers/base.ts`：`ProviderAdapter` 新增 `usageUrl`；`buildSnapshot` 透传。
3. `src/service.ts` 两处手写快照补 `usageUrl`（`''` / `adapter.usageUrl`）。
4. `src/providers/sessionApi.ts` + `presets.ts` 预设类型与 custom 预设补字段；`demo.ts` 定义与适配器补字段；`a1etheropenai.ts` 填 `''`。
5. 四个平台适配器声明用户给定 URL：`qoder.ts` / `trae.ts` / `codebuddy.ts` / `codearts.ts`。
6. 前端：`index.html` 模板改 `<a>`；`styles.css` 增加 `.usage--link` 与 `[hidden]` 收口；`app.js` 的 `renderUsage` 设置 `href`/`aria-label`。
7. `README.md` 适配器示例补 `usageUrl` 一行。
8. 静态检查：`npm run typecheck`；文档状态收口。

## 9. 验证方式

- 静态（本次已执行）：`npm run typecheck`。
- 人工（按 `AGENTS.md` 第 6 节，AI 不代跑动态验证）：
  1. 重启 / 热重载服务，强刷看板（⌘⇧R）；
  2. 四张卡片 hover 用量区 → 出现手型与高亮 → 点击在新窗口打开对应用量页；
  3. A1etherOpenAi 卡片用量区不可点、无 hover 变化；
  4. footer「打开面板」链接保持原样；
  5. 窄屏（≤420px）下四字段仍不溢出、不重叠，整块跳转区域不遮挡文字。
- 回归范围：卡片排序 / 筛选 / 搜索、失败卡片仅显示原因（用量区隐藏）、`/api/summary` 出参结构对既有消费方无破坏。
