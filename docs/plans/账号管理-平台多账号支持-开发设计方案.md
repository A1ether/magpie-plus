## 1. 背景与目标

**结论**：项目的数据层早就支持「一个平台多个账号」（`accounts.json` 是数组，`groupAccounts` / `entries` / `manageAccounts` 契约齐全），但**只有 A1etherOpenAi 一条链路真正打通**；CodeBuddy 这类 Cookie 平台目前既没有看板增删入口，也没有第二个账号的凭证槽位与文档，而 `npm run capture` 每个平台只写一个固定的 `*_COOKIE` 变量。

### 1.1 要解决的问题

| 编号 | 问题 | 现象 |
| --- | --- | --- |
| P1 | 非 A1etherOpenAi 平台没有增删入口 | 前端「＋ 添加账号」的 URL 与文案硬编码 `a1etheropenai`（`public/app.js:682,687,704,711,785`），表单字段也写死「个人 apikey / 项目 apikey」（`public/index.html:108-117`） |
| P2 | 第二个 Cookie 账号没有凭证位置 | `npm run capture` 每平台只写一个 `envKey`（`src/cli/capture.ts:185-191`、`171-175`），再次抓取会覆盖第一个账号的 Cookie |
| P3 | 同名账号会静默串号 | 缓存 / 兜底 / 本地用量采样的键是 `provider#displayName`（`src/service.ts:172`、`src/usage-history.ts:65`）；同名（含都未写 displayName）时键相同，两个账号会共用同一份结果 |
| P4 | 单账号卡片无法删除账号 | 删除按钮只挂在 `entries[]` 的行上（`public/app.js:628`）；像 CodeBuddy 这种「一账号一张卡片」的平台，卡片上没有删除入口 |
| P5 | 配置错误没有提示 | `loadConfig()` 不校验同平台 `displayName` 重复/缺失（`src/config.ts:159-179`），用户看不出 P3 的风险 |

### 1.2 目标

1. **通用机制**：任何适配器只要声明 `manageAccounts: true` + `manageFields`，就获得看板与 CLI 的增删能力，无需改前端。
2. **CodeBuddy 优先落地**：两个账号各自独立取数、独立展示（两张卡片），可看板增删、可 CLI 增删、可 `capture --slot 2` 抓第二个账号的 Cookie。
3. **正确性兜底**：同平台账号键唯一化改造 + 配置重复命名告警。
4. **不碰 A1etherOpenAi 现有行为**：其增删仍走原存储层，保持字节级一致。

### 1.3 Non-Goals（明确不做）

- **不做 CodeBuddy 的「合并成一张卡片」**（不声明 `groupAccounts`）。原因见 §7.2：现有聚合实现会清空合并卡片的 `credits/windows/nextExpiryAt`（`src/aggregate.ts:107-110`），CodeBuddy 的积分批次带真实到期时间，合并后会从「最快到期」时间线消失，与项目核心目标相悖。
- 不新增平台适配器、不改任何平台的上游接口调用与字段解析。
- 不为 Qoder/Trae/MiniMax 等平台开启增删入口（Qoder 有 `options.site` 等表单外的必填语义、MiniMax 是多凭证 + 身份参数），仅把机制做成通用。
- 不改 `npm run a1etheropenai:add` 的既有参数与输出。

## 3. 方案设计

**结论**：把「账号增删」从 A1etherOpenAi 专用实现中抽出一层**平台无关的账号存储层**（`src/account-store.ts`），由适配器的新声明 `manageFields` 驱动前端表单；CodeBuddy 只需声明开关与字段即可接入。多账号的取数、聚合、渲染链路沿用现有机制，仅修掉同名串号问题。

### 3.1 数据流

```
① 添加账号
看板「＋ 添加账号」/ CLI  /  capture --slot N
        │  credentials(明文，仅内存) 或 envRefs(.env 变量名)
        ▼
src/account-store.ts  addManagedAccount()
        │  1) 字段必填校验  2) adapter.probe() 真实验证（通过才写盘）
        │  3) 值去重(409)   4) displayName 唯一(409)
        │  5) 分配 .env 槽位（CODEBUDDY_COOKIE → _2 → _3）
        │  6) 备份 .run/<provider>-add-<ts>/ → 写 .env → 追加 accounts.json
        ▼
accounts.json:  { provider:"codebuddy", displayName:"CodeBuddy · 账号 2",
                  credentials:{ cookie:"${CODEBUDDY_COOKIE_2}" } }

② 取数（既有链路，仅键唯一化）
service.collect()  ── key = `${provider}#${displayName}`（重名时追加 #序号）
        └─ codebuddy.probe() 一账号一 Cookie → 各自快照 → 各自一张卡片
        └─ usage.observe(key)/metricsFor(key) 与缓存键保持一致

③ 删除账号
看板（合并卡片条目 / 单卡片管理面板）/ CLI
        ▼
removeManagedAccount()：按 provider+displayName 定位（0→404 / 多→409）
        → 清掉「不再被任何账号引用」的 .env 变量 → 备份 → 重写 accounts.json
```

### 3.2 职责划分

| 层 | 文件 | 职责 | 本次改动 |
| --- | --- | --- | --- |
| 契约层 | `src/providers/base.ts` | 新增 `manageFields` / `manageHint` / `envNames` 可选声明 | 新增类型，不改既有字段 |
| 适配器层 | `src/providers/codebuddy.ts` | 声明可管理 + Cookie 表单字段 | `manageAccounts: true` + `manageFields` |
| 存储层 | `src/account-store.ts`(新) | 通用增/删/列；A1etherOpenAi 委托旧实现 | 新增 |
| 编排层 | `src/service.ts` | 取数、缓存、采样；**账号键唯一化** | 键计算前移并去重 |
| 配置层 | `src/config.ts` | 解析 accounts.json/.env；**重名告警** | 新增 warnings |
| HTTP 层 | `src/server.ts` | `/api/accounts*` 通用接口 + `/api/providers` 暴露管理描述 | 新增路由（旧路由保留并委托） |
| 前端层 | `public/app.js`、`index.html`、`styles.css` | 按 `manageFields` 动态渲染表单；单卡片也能删账号 | 表单动态化、URL/文案参数化 |
| CLI | `src/cli/account.ts`(新)、`src/cli/capture.ts` | `npm run account` 增删列；`capture --slot N` | 新增 + 小扩展 |

### 3.3 CodeBuddy 多账号的展示形态（本次选择）

| 方案 | 效果 | 结论 |
| --- | --- | --- |
| A. 一账号一张卡片（选中） | 每个账号各自完整的进度条、积分批次、日级用量；「最快到期」时间线保留两个账号的批次（用 `displayName` 区分） | ✅ 信息无损，且不触碰共享聚合代码 |
| B. `groupAccounts: true` 合并一张卡片 | 卡片只剩「账号行 × N」，`credits/windows/nextExpiryAt` 被清空（`src/aggregate.ts:107-110`） | ❌ 见 §7.2 |

## 4. 接口设计

### 4.1 ProviderAdapter 契约扩展（`src/providers/base.ts`）

```ts
/** 看板「＋ 添加账号」表单里的一个输入项；字段名必须是 credentials 的键 */
export interface ManageFieldDescriptor {
  key: string;              // 如 'cookie'
  label: string;            // 如 'Cookie'
  placeholder?: string;
  hint?: string;
  required?: boolean;       // 默认 true
  multiline?: boolean;      // Cookie 很长 → 用 textarea
  secret?: boolean;         // 默认 true → type=password
}

interface ProviderAdapter {
  // …既有字段不变
  manageAccounts?: boolean;              // 已存在
  manageFields?: ManageFieldDescriptor[]; // 新增：声明后才开放通用增删
  manageHint?: string;                    // 新增：表单底部提示文案
  envNames?: Record<string, string>;      // 新增：credentials 键 → .env 变量名前缀（默认推导）
}
```

`.env` 变量名推导规则：`envNames[key]` 优先，否则 `${PROVIDER_ID.toUpperCase()}_${KEY.toUpperCase()}`（CodeBuddy → `CODEBUDDY_COOKIE`，与原约定一致）。**槽位 1 用无后缀名，第 N 个账号用 `<名前缀>_N`**（`CODEBUDDY_COOKIE_2`）。

### 4.2 HTTP 接口（`src/server.ts`）

| 路径 | 方法 | 入参 | 出参 | 错误 |
| --- | --- | --- | --- | --- |
| `/api/providers` | GET | — | 每项新增 `manageAccounts` / `manageFields` / `manageHint` / `groupAccounts` | — |
| `/api/accounts` | GET | query `provider` | `{ provider, accounts:[{id,label,enabled,complete,previews,envRefs}], warnings, missingEnvVars }` | 404 未知平台 |
| `/api/accounts/add` | POST | `{ provider, credentials?, envRefs?, name?, force?, dryRun? }` | `{ ok, provider, name, credentials, backupDir, account:{label,amount,currency,note,secrets}, details[] }` | 400 缺字段/验证失败；403 平台未开放；409 重复值/重名；500 写入失败（带 `stage`） |
| `/api/accounts/remove` | POST | `{ provider, accountId }` | `{ ok, name, removedEnvLines, backupDir }` | 404 找不到；409 同名多条；500 写入失败 |

约定与既有 `/api/a1etheropenai/accounts*` 完全一致：

- 三个接口都过 `privilegedGuard`（`src/server.ts:81-103`）；
- `credentials` 为**明文**、只存在于请求与内存，落盘一律写成 `${VAR}` 引用；响应只回掩码；
- `envRefs` 是「引用 `.env` 里已有变量」的另一种入参（`{ cookie: "CODEBUDDY_COOKIE_2" }`），用于 `capture --slot` + CLI 的两步流程；
- 旧的三个 `a1etheropenai` 路由**保留**（CLI 与既有脚本依赖），内部与通用接口共用同一份实现。

### 4.3 CLI

| 命令 | 说明 |
| --- | --- |
| `npm run account -- --list [--provider codebuddy]` | 列出已配置账号（启用状态、掩码预览、env 变量引用） |
| `npm run account -- --provider codebuddy --cookie '<值>' [--name '...'] [--force] [--dry-run]` | 粘贴凭证新增（凭证 flag 名 = `manageFields[].key`） |
| `npm run account -- --provider codebuddy --env CODEBUDDY_COOKIE_2 [--name '...']` | 引用 `.env` 已有变量新增（不复制明文） |
| `npm run account -- --remove 'CodeBuddy · 账号 2' [--provider codebuddy]` | 删除账号并清理不再引用的 .env 变量 |
| `npm run capture -- codebuddy --slot 2` | 把当前登录账号的 Cookie 抓到 `CODEBUDDY_COOKIE_2`（`--slot` 缺省 = 1，写原有变量） |

`capture --slot N`（N≥2）对所有 `envKey/tokenEnvKey/identity envKeys` 统一加 `_N` 后缀，`HTTP_USER_AGENT` 不参与。抓取完成后打印下一步命令：`npm run account -- --provider <id> --env <VAR> --name '...'`。

## 5. 数据模型

### 5.1 `types.ts`

**不改动**。`ProviderSnapshot` / `ProviderEntry` / `CreditLot` 契约已满足「多账号 + 各一张卡片」的需求（本次不启用合并卡片）。

### 5.2 `accounts.json`

新增一个**同平台第二个账号**的写法：`displayName` 必须唯一（这是账号稳定标识），凭证各自引用不同的 `.env` 变量。

```jsonc
// 新增（第二个 CodeBuddy 账号）；原账号保持不动
{
  "provider": "codebuddy",
  "displayName": "CodeBuddy · 账号 2",
  "enabled": true,
  "credentials": { "cookie": "${CODEBUDDY_COOKIE_2}" },
  "options": {}
}
```

`accounts.example.json` 会同步补上这条示例（`enabled: false`）与说明注释。

### 5.3 `.env`

```bash
CODEBUDDY_COOKIE=…      # 账号 1（槽位 1，无后缀，保持历史约定）
CODEBUDDY_COOKIE_2=…    # 账号 2（槽位 2，由看板/CLI 自动分配，无需手工起名）
```

### 5.4 是否需要迁移？

**不需要**。既有配置完全兼容：

- 单账号平台行为不变（未声明 `manageFields` 的平台既不显示入口也不会被写入）；
- A1etherOpenAi 的 `A1etherOpenAi_<字母>_API_KEY` 命名与增删流程不变（走原存储层）；
- 唯一的隐形变化是**同平台重名账号的缓存键**会从 `provider#名字` 变成 `provider#名字#序号`，可能让这两个账号的本地采样历史重置一次（见 §7.3）。

## 7. 风险与备选方案

### 7.1 主要风险

| 风险 | 等级 | 降级 / 应对 |
| --- | --- | --- |
| 通用接口误开放给不该管理的平台 | 中 | 白名单：只有声明了 `manageAccounts` **且**给了 `manageFields` 的适配器才放行；A1etherOpenAi 走专用存储层 |
| 写入 .env/accounts.json 失败留下半截配置 | 中 | 沿用既有范式：写入前备份到 `.run/`，`.env` 先写、accounts.json 后写，失败即返回 500 并提示备份路径 |
| 槽位变量被别的账号引用却误删 | 中 | 删除时只清「不再被任何同平台账号引用」的变量（与 `removeA1etherOpenAiAccount` 同策略） |
| 前端表单动态化引入 XSS/注入 | 低 | 一律用 `createElement` + `textContent` 构建（沿用现有 `element()` 工具），不用 `innerHTML` |
| 用户粘贴的 Cookie 卡住页面（超长文本） | 低 | 用 `textarea` + 提交前 `trim()`；服务端不做长度上限（Cookie 本身可达数 KB） |

### 7.2 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| CodeBuddy 声明 `groupAccounts: true`（一张卡片两条账号） | `finalizeCard()` 会把合并卡片的 `credits/windows/nextExpiryAt` 清空（`src/aggregate.ts:107-110`），CodeBuddy 的积分包有真实到期时间，合并后将不再出现在「最快到期」时间线与卡片批次列表，违背项目核心目标；要合并就得同时改造 `types.ts`（条目携带批次）+ 聚合 + 时间线 + 前端条目渲染，改动面远超本次需求 |
| 继续用 `provider#displayName` 当键，仅靠文档要求不重名 | 静默串号比报错更糟：两个账号会显示同一份额度且无人发现；本次用「配置告警 + 键唯一化」双保险 |
| 直接把 `a1etheropenai-store.ts` 改造成全平台通用 | 该文件承载「两把密钥验证 + 字母槽位 + revealApiKey」等专用语义，改造会波及已稳定的 A1etherOpenAi 链路；改为新增通用层 + 委托，风险最低 |
| `capture --slot` 顺带自动写 accounts.json | 抓取与写配置耦合后，验证失败会留下「有登录态但没账号」的中间状态，且抓取脚本要理解各平台凭证映射；拆成两步（抓取 → `npm run account --env`）更可控 |

### 7.3 已知取舍

- **键唯一化的历史影响**：重名账号（原本就串号）的本地采样历史会重置一次，日级用量的「本地采样」来源在当天可能显示 `null`；下一次采样后恢复。未重名的账号不受影响。
- **单卡片账号的删除入口**在「＋ 添加账号」面板里（而非卡片正文），因为单卡片没有可挂靠的密钥行；合并卡片仍保留条目行内的删除按钮。
